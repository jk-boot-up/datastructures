1. Static Array

Hello, and welcome. This video explains the static array, in C. This video is presented by Jayasekhar Konduru. First, a simple definition. A static array stores elements of the same type in consecutive memory locations. Each element has an index, starting from zero. Because the elements are consecutive, the address of any element is calculated in one step. And the capacity is fixed when the array is created. Our example is a weather station, storing one temperature a day. By the end, you will know every textbook array operation, what each one costs in time and in space, and how the array compares with a dynamic array and a linked list.

2. The Everyday Idea

Think of a row of numbered lockers in a school corridor. Locker zero, locker one, locker two, all the same size and all touching. If someone says, open locker three, you do not search. You walk straight to it. But to fit a new locker into the middle, every locker after it would have to move. And when the corridor is full, there is no room for another. That is an array.

3. The Words

The words a textbook uses. An index is an element's position, from zero. The base address is where element zero starts in memory. The capacity is the number of places, fixed when the array is created. And n is the number of elements actually stored. Inserting into a full array is an overflow. Deleting from an empty one is an underflow.

First, the week without an array. Seven separate variables, one for each day. To find the maximum, we must write six comparisons, one after another, by hand. And to ask for day number three, we need a switch with seven branches. Nothing connects the seven variables.

5. Seven separate variables

Here are the seven variables. Each has its own name, and there is no index. Without an index, a loop cannot visit them, so every question names all seven days.

6. Act Two — One array: int arr[10], n = 7

Now the same week in one array. We reserve ten places, side by side in memory, and store the seven days in the first seven. So the capacity is ten, and n, the number of elements, is seven. Each element takes four bytes. So the address of element three is the base address, plus three times four.

7. One array: int arr[10], n = 7

Here is the array. The small numbers above are the indexes, from zero to nine. The first seven hold the week. The last three, dashed, are free. n, the number of elements, points at the first free place.

8. One array: int arr[10], n = 7

How does the computer find element three? It takes the base address, where element zero starts, and adds three times four bytes. One calculation. Element three, or element three million, costs the same single step. That is order one access.

9. Act Three — Access, update, search

Now we count. Get element three: one step. Update element five to twenty six: one step. Searching for a value is different. Linear search compares with each element in turn. It finds twenty four after five comparisons, and needs all seven to learn that thirty is not there. On a sorted array, binary search finds twenty four in three.

10. Access, update, search

Linear search for twenty four. Index zero, no. One, no. Two, no. Three, no. Index four matches. Five comparisons.

11. Access, update, search

Binary search, on the sorted week. The middle element is twenty three: too small, so the left half is discarded. The middle of what is left is twenty five: too big. Then twenty four. Three comparisons. Each comparison halves the range, so a million elements need only twenty.

12. Act Four — Insertion, deletion, overflow

Now insertion and deletion. A late reading, eighteen, must go at index two. The elements from index two onwards shift one place right, starting from the end. Five shifts. Deleting the element at index zero shifts seven elements left. And when all ten places are full, the next insertion is an overflow.

13. Insertion, deletion, overflow

Here is the array after the insertion. Eighteen, in purple, is at index two. The five elements after it, in amber, each shifted one place to the right, starting from the end. Five shifts for one insertion.

14. Insertion, deletion, overflow

Now the array is full. Ten elements, in ten places. There is no eleventh place, so the next insertion is refused. That is an overflow. A static array cannot grow.

15. Act Five — The bill

And the bill. On a million sorted elements, binary search needs twenty comparisons. Linear search needs a million. Both are loops, so both use only a few extra variables: order one extra space. And the capacity never changes. To grow from seven to thirty one places, we allocate a new array and copy every element.

16. The bill

Here is the grow. The old array of seven, and a new array of thirty one. The seven elements are copied across, in purple. The old array is discarded. Growing a static array always costs one copy per element.

17. Time and Space Complexity

Here are the costs in time and space. Access and update are order one. Traversal, linear search, finding the maximum, and reversal are order n. Binary search on a sorted array is order log n. Insertion and deletion are order n at the front, because of the shifts, and order one at the end. And every operation here is a loop, so the extra space is order one.

18. Compared With Related Structures

How does the static array compare? Access by index is order one in an array, and order n in a linked list. Insertion at the front is order n in an array, and order one in a linked list. A static array's size is fixed, while a dynamic array grows by copying. And only an array can binary search, because only an array can jump to its middle.

19. Common Mistakes

Five mistakes to watch for. Counting indexes from one. Looping while i is less than or equal to n, which goes one past the last element. Shifting in the wrong direction on insertion, which overwrites the data. Binary search on unsorted data. And computing the middle as low plus high over two, which can overflow.
