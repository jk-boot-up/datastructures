# Linked List Reverse - Maven Project Structure

## Overview

This project demonstrates the implementation of a **generic singly linked list** in Java with support for reversing the list using an iterative algorithm. The project follows the **standard Maven directory layout**, making it easy to build, test, and maintain.

The project produces a **JAR** file and is built using **Java 17** and **Maven**.

---

| Property | Value |

| Artifact Id | `linkedlist-reverse` |

# Directory Explanation

## pom.xml

The `pom.xml` (Project Object Model) is the heart of every Maven project.

It defines:

- Project metadata
- Dependencies
- Java version
- Build plugins
- Packaging type

```
pom.xml
```

Everything Maven needs to build the project is configured here.

---

## src/main/java

Contains the production source code.

```
src
└── main
    └── java
```

Inside this directory are all Java classes that become part of the final application.

Example

```
src/main/java
└── org
    └── jk
        └── dsa
            ├── LinkedList.java
            └── Main.java
```

---

## LinkedList.java

Contains the complete implementation of the generic linked list.

Responsibilities include:

- Creating nodes
- Adding elements
- Inserting at an index
- Reversing the list
- Printing the list
- Maintaining head and tail pointers

---

## Main.java

Contains the application's entry point.

```java
public static void main(String[] args)
```

Typical responsibilities include:

- Creating a linked list
- Adding sample elements
- Calling `reverse()`
- Displaying the results

Example

```java
LinkedList<Integer> list = new LinkedList<>(10);

list.add(20);
list.add(30);
list.add(40);

System.out.println(list);

list.reverse();

System.out.println(list);
```

---

# src/test/java

Contains all unit tests.

```
src
└── test
    └── java
```

Example

```
LinkedListTest.java
```

This folder should contain JUnit test classes that verify:

- addFirst()
- addLast()
- add(index)

- isEmpty()
- toString()

Keeping test code separate from production code is a standard Maven convention.

    ...

## Lombok

```xml
<dependency>
    <groupId>org.projectlombok</groupId>
    <artifactId>lombok</artifactId>
    <version>1.18.42</version>
</dependency>
```

Purpose:

Reduces boilerplate code by automatically generating:

- Getters
- Setters
- `toString()`
- Constructors (when requested)
- `equals()`
- `hashCode()`

Example

Instead of writing

```java
public T getData() { ... }

public void setData(T data) { ... }
```

Lombok generates them automatically using annotations like:

```java
@Getter
@Setter
@ToString
```

# Maven Plugins

## Maven Compiler Plugin

```xml
<plugin>
    <artifactId>maven-compiler-plugin</artifactId>
</plugin>
```

Purpose:

- Compiles Java source code
- Uses Java 17 (`<release>17</release>`)
- Produces `.class` files under `target/classes`

---

## Maven Surefire Plugin

```xml
<plugin>
    <artifactId>maven-surefire-plugin</artifactId>
</plugin>
```

Purpose:

- Discovers JUnit tests
- Executes all test classes
- Generates test reports
- Fails the build if any test fails

Running

```bash
mvn test
```

automatically invokes the Surefire plugin.

# Common Maven Commands

## Clean the project

```bash
mvn clean
```

Deletes the `target` directory.

---

## Compile source code

```bash
mvn compile
```

Compiles Java source files.

---

## Run unit tests

```bash
mvn test
```

Executes all JUnit tests.

---

## Package the project

```bash
mvn package
```

Performs the following steps:

1. Compiles the project
2. Runs all tests
3. Creates the JAR file

---

## Install into the local Maven repository

```bash
mvn install
```

Copies the generated JAR into the local Maven repository (`~/.m2/repository`) so it can be used as a dependency by other Maven projects.

# Build Lifecycle

The Maven build process follows this sequence:

```
clean
   │
   ▼
compile
   │
   ▼
test
   │
   ▼
package
   │
   ▼
install
```

Each phase depends on the successful completion of the previous phase.

- Easy integration with IDEs such as IntelliJ IDEA and Eclipse.
- Simplified build, testing, and packaging processes.

# Summary

This project follows the standard Maven project layout and uses Java 17 to implement a generic singly linked list. Production code resides under `src/main/java`, while unit tests are placed under `src/test/java`. Maven manages dependencies such as JUnit 5 and Lombok, compiles the source code using the Maven Compiler Plugin, executes tests with the Maven Surefire Plugin, and packages the application as a JAR file. By adhering to Maven conventions, the project remains organized, portable, and easy to build and maintain.
