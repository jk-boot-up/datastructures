1. Dynamic Array (Generic)

Hello, and welcome. This video explains the generic dynamic array, in Java. This video is presented by Jayasekhar Konduru. First, a simple definition. A generic dynamic array is an array that grows by itself, written once for any type of element. It stores references to objects, and doubles its room when it is full. Our example is a music playlist of songs. By the end, you will know how Java's array list is built, what a resize really copies, and why deleted places must be cleared.

2. The Everyday Idea

Think of moving house, but with a warehouse. Your furniture stays in the warehouse, and you keep a list of where each piece is. When the list runs out of lines, you copy it onto a sheet twice as long. Only the addresses are copied. The furniture never moves. And the list does not care whether the addresses point at chairs, or books, or bicycles.

3. The Words

The words. T is the element type, filled in each time the class is used. Size is how many elements are in use, and capacity is how many places there are. Each place holds a reference, the address of an object. A resize copies the references, not the objects. And equals compares contents.

4. Act One — One class, any element type

First, one class for any type. The same dynamic array holds song titles, as strings. It holds play counts, as integers. And it holds songs, a type of our own. Inside each is an ordinary array of four places. It is created as an array of object, because Java cannot create an array of T directly.

5. One class, any element type

Here are two of them. Titles and play counts. The same class, the same code, four places each, three in use.

6. Act Two — Full? Double it, copying references

Now the playlist fills up. Appending a fifth song needs a resize: a new array of eight places. Four references are copied across. Not four songs: four addresses. The song at index zero is still the very same object. Nine songs take two resizes, exactly as before.

7. Full? Double it, copying references

Here is the resize. The old array of four, and the new array of eight. Each place holds an arrow to a song. The arrows are copied, and the songs stay put.

8. Act Three — The middle, and equals

Now the middle. Inserting an intro at the front shifts nine songs. Deleting index five shifts four. Then we make a new song called Echoes, with the same length, and search for it. Search uses equals, and a record's equals compares the title and the length. So it is found, at index six, although it is a different object.

9. The middle, and equals

Here is the search. Six songs compared, and not equal. The seventh, Echoes, is equal: same title, same length. Seven comparisons.

10. Act Four — Deleting clears references

Deleting is where references matter most. Deleting the last song sets its place to null. If the array kept the reference, the song could never be freed from memory. That is a memory leak. Then shrink to fit copies eight references into exactly eight places.

11. Deleting clears references

Here is the array after the deletion. Eight songs. The place that held Last Train is now null, like every spare place.

12. Act Five — The bill

And the bill. A thousand appends copy one thousand and twenty references. About one per append. Deleting down to a quarter halves the capacity. Every cost is the same as the string-only version. Generics change the type, not the algorithm. And this is how Java's array list is built.

13. The bill

Here are the copies at each resize. Four, eight, sixteen, doubling each time, up to five hundred and twelve. One thousand and twenty in all, for a thousand appends.

14. Time and Space Complexity

Here are the costs in time and space. Append is order one amortised, and order n when it resizes. Get and update are order one. Insert and delete at the front are order n. Linear search is order n. Every one of them is the same as the string-only version.

15. Compared With Related Structures

How does it compare? The string-only dynamic array has the same costs, but holds one type. The generic static array holds any type, but cannot grow. A plain int array stores values, not references, so it uses less memory. And Java's own array list is exactly this structure.

16. Common Mistakes

Four mistakes to watch for. Writing new T array, which does not compile. Searching with double equals, which misses equal objects. Not clearing freed places, which leaks memory. And growing by a fixed amount instead of doubling.
