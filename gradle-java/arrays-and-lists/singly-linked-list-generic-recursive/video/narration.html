1. Singly Linked List (Generic, Recursive)

Hello, and welcome. This video explains the generic, recursive singly linked list, in Java. This video is presented by Jayasekhar Konduru. First, a simple definition. It is a chain of nodes holding any type of data, where every operation calls itself on the rest of the list. Elements are matched with equals, and every call waiting uses a frame on the call stack. Our example is a treasure hunt of clues. By the end, you will know how generics and recursion combine on a list, the same way they will on trees.

2. The Everyday Idea

Think of a line of finders, each holding a card. The cards could be places, numbers, or photographs. You ask the first finder whether their card matches yours. If not, they ask the next finder, and wait. Each finder only needs to know how to compare two cards. That is a generic, recursive list.

3. The Words

The words. A node of T holds data of type T, and the rest of the list. Equals compares contents. The base case is the empty list, or the match. A changing method returns the new first node. And the depth is one frame per node visited.

12. Act Five — The limit of recursion

And the limit. A million nodes. Counting them recursively needs a million frames. The stack overflows. Generics change what a node refers to. Recursion changes how much stack a walk needs.

13. The limit of recursion

One count call per node. Far too many.

14. Time and Space Complexity

Here are the costs. Insertion and deletion at the beginning are order one. Search, count and display take order n time and stack. So do insertion and deletion at the end, and reverse. The loop version takes the same time, with order one space.

15. The Four Singly Linked Lists

The four singly linked lists. Strings with loops. Strings with recursion. Any type with loops. And any type with recursion, this one. On a million nodes, only the loop versions finish.

16. Common Mistakes

Four mistakes. Not storing the returned node. Matching with double equals. Forgetting the empty list. And recursing over long lists.
