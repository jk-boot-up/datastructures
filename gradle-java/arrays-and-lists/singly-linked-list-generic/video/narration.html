1. Singly Linked List (Generic)

Hello, and welcome. This video explains the generic singly linked list, in Java. This video is presented by Jayasekhar Konduru. First, a simple definition. It is a chain of nodes, written once for any type of data. Each node holds a reference to its data, and a pointer to the next node. Our example is a treasure hunt, held as place names, as distances, and as clues. By the end, you will know how to write a generic node and list, what a node really holds, and why elements are matched with equals.

2. The Everyday Idea

Think of the treasure trail again. Each signpost holds a slip saying where this stop's prize is kept, and points to the next signpost. The trail does not care whether the prizes are coins, books, or maps. The signposts work the same for all of them. That is a generic linked list.

3. The Words

The words. T is the element type, filled in at each use. A node of T holds data of type T, and a next pointer. The data is a reference: the node points at the object. And equals compares contents, not references.

4. Act One — One class, any element type

First, one class for any type. The same linked list holds the place names, as strings. It holds the distances, as integers. And it holds clues, a type of our own. The compiler checks each one. Putting a word into the list of distances does not compile.

5. One class, any element type

Here are two of the lists. Distances, and place names. The same nodes, the same next pointers, different data.

6. Act Two — Node<T>: data is a reference

What does a node hold? Two references. One to the clue, which lives elsewhere in memory. And one to the next node. The node does not contain a copy of the clue. It points at it. Counting is still six steps along the next pointers.

7. Node<T>: data is a reference

Here is one node. Its data arrow goes to the clue. Its next arrow goes to the next node.

8. Act Three — Search and deletion with equals

Now search. We make a new clue: the fountain, fifty metres. Search compares with equals, and a record's equals compares its fields. So it is found, at position four. But it is a different object: double equals would have missed it. Insertion and deletion change pointers exactly as before.

9. Search and deletion with equals

Here is the search. Four clues that are not equal. The fifth, the fountain at fifty metres, is equal. Five comparisons.

10. Act Four — Deleting at both ends

Deleting at both ends. Deleting at the beginning moves the head: one pointer. Deleting at the end walks to the node before the last: three steps. Nothing refers to the removed nodes now, so Java can free them. And deleting from an empty list is an underflow.

11. Deleting at both ends

Here is the list now. The mill is at the head, and the fountain's next is null.

12. Act Five — The same algorithm for every type

One algorithm for every type. Reverse turns every next pointer around. On the distances, seven pointer changes. On the place names, the very same seven. Generics change the type of the data. They do not change the algorithm, or its cost.

13. The same algorithm for every type

Here are the reversed distances. The last became the first, and no number moved.

14. Time and Space Complexity

Here are the costs. Insertion and deletion at the beginning are order one. At the end, order n. At a position, order n to reach it, and order one to link. Search, get, count, display and reverse are order n. Exactly the same as the string-only list.

15. Compared With Related Structures

How does it compare? The string-only list has the same costs, for one type. The generic dynamic array reaches any position in one step, but needs a cast inside. The generic list needs no cast at all. And Java's own linked list is generic in the same way, linked in both directions.

16. Common Mistakes

Four mistakes to watch for. Matching with double equals. Using the raw types without angle brackets. Setting the insertion pointers in the wrong order. And changing an object after inserting it, forgetting that the list shares it.
