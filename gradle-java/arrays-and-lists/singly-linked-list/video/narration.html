1. Singly Linked List

Hello, and welcome. This video explains the singly linked list, in Java. This video is presented by Jayasekhar Konduru. First, a simple definition. A singly linked list is a chain of nodes. Each node holds its data, and a next pointer to the following node. The list remembers only the first node, called the head. Inserting or deleting changes a pointer or two, and no data moves. Our example is a treasure hunt, where each clue says where the next one is. By the end, you will know every textbook operation on a linked list, what each one costs, and the one mistake that loses half the list.

2. The Everyday Idea

Think of a treasure hunt. You are handed the first clue. It says: the next clue is under the oak tree. Under the oak tree, a clue sends you to the old well. Nobody has a map of every clue. Each clue only knows where the next one is. To add a clue, you rewrite one clue to point at the new spot. But to reach the last clue, you must walk the whole trail. That is a linked list.

3. The Words

The words a textbook uses. A node holds its data, and a next pointer. The head is the first node, and it is the only one the list stores. Null is the next pointer of the last node, and marks the end. And current and prev are the two pointers used to walk the list.

4. Act One — The hunt in an array

First, the hunt stored in an array. Six clues, at indexes zero to five. The organisers want a new clue, the mill, at index one. An array cannot open a gap. So five clues shift one place to the right. Every insertion near the front shifts nearly everything.

5. The hunt in an array

Here is the array after the insertion. The mill is at index one, in purple. The five clues after it, in amber, each shifted one place to the right. Five shifts for one new clue.

6. Act Two — Nodes and next pointers

Now the same hunt as a linked list. Each clue is a node, holding its data and a next pointer. The last next pointer is null. The list itself remembers only the head, the first node. Inserting at the end must walk to the last node every time: ten steps to build the hunt. And counting the clues means walking all six nodes.

7. Nodes and next pointers

Here is the list. Head points to the oak tree. Each node points to the next. The chest's next pointer is null: the end. The nodes can be anywhere in memory; the pointers put them in order.

8. Act Three — Search, insertion and deletion

Now the textbook operations. Search compares node after node: five comparisons to find the fountain. Inserting the mill at position one walks to the oak tree, then changes two pointers. Nothing shifts. Inserting at the beginning also changes two pointers. Deleting the red gate points the old well past it: one pointer. Deleting at the beginning moves the head. And deleting at the end walks to the node before the last.

9. Search, insertion and deletion

Here is the insertion. First, the new node, the mill, points to the old well. Then the oak tree points to the mill. Two pointers changed, and no clue moved.

10. Search, insertion and deletion

And the deletion. We walk with two pointers, prev and current. When current reaches the red gate, prev, the old well, is pointed past it, to the bridge. One pointer changed. The red gate can no longer be reached.

11. Act Four — Two pointers in the wrong order

What happens if the two pointers are set in the wrong order? First, the old well is pointed at the mill. Now nothing points to the red gate. Then the mill copies the old well's pointer, which points at the mill itself. The mill points at itself. Only three clues can be reached. The other four are lost.

12. Two pointers in the wrong order

Here is the broken list. The oak tree, the old well, and the mill, which points back at itself. The four clues after it, in red, still exist, but no pointer leads to them.

13. Act Five — Reversal, and the bill

Now reversal. Three pointers walk the list: previous, current, and next. Each node's next pointer is turned around to point backwards. Seven pointer changes, and no clue moves. And the bill. Reaching position nine hundred and ninety nine takes nine hundred and ninety nine steps. An array takes one.

14. Reversal, and the bill

Here is reversal half way. The nodes behind current already point backwards. Next holds on to the rest of the list, so nothing is lost when current's pointer is turned.

15. Time and Space Complexity

Here are the costs in time and space. Insertion and deletion at the beginning are order one. Insertion and deletion at the end are order n, because only the head is stored. At a position, reaching it is order n, and linking is order one. Search, get, count, display and reverse are order n. And every operation uses order one extra space.

16. Compared With Related Structures

How does it compare? Reaching position i is order n in a list, and order one in an array. Inserting at the beginning is order one in a list, and order n in an array. Deleting at the end is order n in a singly linked list, and order one in a doubly linked list. And every node carries a pointer, so a list uses more memory than an array.

17. Common Mistakes

Four mistakes to watch for. Setting the two pointers of an insertion in the wrong order, which loses the rest of the list. Walking with the head instead of a current pointer. Forgetting the empty list, and the list of one node. And trying to delete a node without holding the node before it.
