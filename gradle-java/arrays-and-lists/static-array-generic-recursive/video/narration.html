1. Static Array (Generic, Recursive)

Hello, and welcome. This video explains the generic, recursive static array, in Java. This video is presented by Jayasekhar Konduru. First, a simple definition. It is a static array written once for any element type, whose operations call themselves. Each call handles one element, compares it with equals or compare to, and passes the rest to the next call, until a base case stops it. Our example is a weather station's week, as day names, temperatures, and readings. By the end, you will know how generics and recursion work together, and what each one costs.

2. The Everyday Idea

Think of a queue of seven people, each holding a card. You want to find a card that matches yours. The first person compares their card with yours. If it does not match, they ask the person behind them, and wait. The cards could be numbers, names, or photographs. Each person just knows how to compare two cards of that kind. When someone finds a match, or the queue runs out, the answer travels back up. Everyone waiting is the call stack.

3. The Words

The words. T is the element type, filled in each time the class is used. Equals asks whether two elements have the same contents. Compare to asks which one is larger. The base case answers without calling again. The recursive case handles one element and calls itself on the rest. And the recursion depth, the number of frames at once, is the extra memory used.

4. Act One — Recursion, for any element type

First, recursion for any element type. Recursive linear search asks one question. Is the element here equal to the key? If not, search the rest, by calling itself, and wait. Monday, no. Tuesday, no. Wednesday, no. Thursday, yes. That is a base case: the search stops. Four calls, four frames on the stack.

12. Act Five — The limit of recursion

And the limit. Binary search on a million integers is only twenty calls deep. Linear search needs one frame per element, and the call stack runs out: a stack overflow error. So, generics change what is compared. Recursion changes how much stack is used. Neither changes the time.

13. The limit of recursion

Here are the two depths. Twenty frames for binary search. A million frames for linear search, far beyond what the call stack can hold.

14. Time and Space Complexity

Here are the costs. Get and update are order one, and not recursive. Traversal, linear search and find max take order n time, and order n stack. Binary search takes order log n time and stack. Insertion and deletion at the front take order n time and stack. The loop versions take the same time, with order one extra space.

15. The Four Static Arrays

How do the four static arrays compare? The int array with loops is the fastest and the smallest. The recursive int array adds a stack frame per waiting call. The generic array with loops holds any type, through references. And this one does both. Generics change what is compared. Recursion changes how much stack is used.

16. Common Mistakes

Four mistakes to watch for. Using double equals or less than on elements, instead of equals and compare to. A recursion with no base case, or no progress towards it. Leaving the deleted reference in the array. And linear recursion on large data, which overflows the stack.
