1. Static Array (Generic)

Hello, and welcome. This video explains the generic static array, in Java. This video is presented by Jayasekhar Konduru. First, a simple definition. A generic array is written once, with a type parameter called T. Each time it is used, T is filled in: integers, strings, or any type of our own. Everything else is the static array you already know. Our example is a weather station's week, stored three different ways by the same class. By the end, you will know how to write a generic array, what it really stores, and why objects are compared with equals and compare to.

2. The Everyday Idea

Think of the row of numbered lockers again. But now each locker holds a label, with an address, and the thing itself is kept somewhere else. The lockers do not care what the things are, so the same row works for books, or for bicycles. When the manager says, this row is for books only, nobody may store a bicycle's label there. That is a generic array: one design, any type, and a rule that is checked.

3. The Words

The words. T is the type parameter, filled in each time the class is used. Each place stores a reference, the address of an object. Equals asks whether two objects have the same contents. Compare to asks whether one is smaller, equal, or larger. And T extends comparable means: any type whose elements can be put in order.

4. Act One — One class, any element type

First, one class for any type. The same generic array holds the temperatures, as integers. It holds the day names, as strings. And it holds readings, a type of our own. The type is written in angle brackets, and the compiler checks it. Putting a word into the array of integers does not even compile.

5. One class, any element type

Here are the three arrays. The same class, the same code. Only the type in angle brackets changes. Integer, string, and reading.

6. Act Two — Inside: an array of references

What does the array really hold? Java cannot create an array of T directly, because T is forgotten when the program runs. So the class creates an array of comparable things, and casts it. Each place holds a reference: the address of an object stored elsewhere. Copying the array copies seven references, not seven objects. Both arrays point at the same objects.

7. Inside: an array of references

Here is the picture. The array holds references, drawn as arrows. The objects themselves are elsewhere. Following the arrow is one more step than reading an int.

8. Act Three — Searching with equals and compareTo

Now searching. With objects, double equals only asks: is this the very same object? A new string, Fri, made separately, is a different object, so double equals says false. So linear search uses the equals method, which compares the contents. Binary search needs order, so it uses compare to. It finds twenty four in three comparisons, and Thursday among the sorted day names in three as well.

9. Searching with equals and compareTo

Binary search on the sorted day names. The middle is Sunday. Thursday comes after it alphabetically, so go right. The middle of the right half is Tuesday. Thursday comes before it, so go left. And there is Thursday. Three comparisons.

10. Act Four — Insertion, deletion, overflow

Insertion and deletion work exactly as before. Inserting a reading at index two shifts five references right. Deleting index zero shifts seven references left. Then one extra step: the freed place is set to null. Otherwise the array would keep the deleted object alive. And when all ten places are used, the next insertion is an overflow.

11. Insertion, deletion, overflow

Here is the array after the deletion. Seven references, in amber, shifted one place to the left. The place after them, which used to hold a copy of the last reference, is now null.

12. Act Five — One algorithm, many orders

One algorithm, many orders. Find max is written once. For readings, it compares temperatures, and returns Thursday, twenty five degrees. For day names, it compares alphabetically, and returns Wednesday. Each type brings its own order. And there is no sum here, because adding needs numbers, and T can be any type.

13. One algorithm, many orders

Here is find max on the readings. Six comparisons, each asking a reading to compare itself with the largest so far. Thursday, at twenty five degrees, wins.

14. Time and Space Complexity

Here are the costs in time and space. They are exactly the same as the int array. Access and update are order one. Traversal, linear search, maximum and reverse are order n. Binary search is order log n. Insertion and deletion are order n at the front. Generics change the element type, not the algorithm.

15. Compared With Related Structures

How does it compare? An int array stores the values themselves, four bytes each. A generic array stores references, and every value is a separate object, so it uses more memory. An int array compares with double equals and less than. A generic array uses equals and compare to. And like every static array, its capacity is fixed. A generic dynamic array grows.

16. Common Mistakes

Four mistakes to watch for. Comparing objects with double equals, which only checks for the very same object. Writing new T array, which does not compile. Leaving a reference in a freed place, which keeps the object alive. And using the class without a type in angle brackets, which switches the compiler's checks off.
