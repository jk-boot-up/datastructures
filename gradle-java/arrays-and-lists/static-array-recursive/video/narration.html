1. Static Array (Recursive)

Hello, and welcome. This video explains the static array, written recursively, in Java. This video is presented by Jayasekhar Konduru. First, a simple definition. A recursive method solves a problem by handling one small piece, and calling itself for the rest. It stops at a base case, where nothing is left to do. Every call that is still waiting uses memory on the call stack. Our example is a weather station, storing one temperature a day in an array. By the end, you will know how to write every textbook array operation recursively, what each one costs in time and in memory, and when a loop is the better choice.

2. The Everyday Idea

Think of a queue of seven people. You want the total money in their pockets. You ask the first person. They ask the person behind them for the total from there to the end, and wait. That person asks the next, and waits too. The last person has nobody behind, so they answer at once. That is the base case. Then the answers travel back up, each person adding their own amount. While everyone waits, they are all standing in the queue. That is the call stack.

3. The Words

The words a textbook uses. The base case is the smallest input, answered without calling again. The recursive case handles one element and calls the method for the rest. The call stack holds one frame for every call that is still waiting. The recursion depth is how many frames there are at once, and that is the extra memory used. If the depth is too great, the stack overflows.

4. Act One — Thinking recursively

First, how to think recursively. The sum of the week is the first temperature, plus the sum of the rest. And the sum of the rest is its first temperature, plus the sum of what is left. This keeps going until nothing is left. The sum of nothing is zero. That is the base case. The answer is one hundred and fifty four, and seven calls were waiting at the same time.

7. Act Two — The call stack

Where do the waiting calls live? On the call stack. Each call that has not finished keeps a frame, holding its own index. Traversal visits one element and calls itself for the rest. At the end, seven frames are on the stack at once. One frame per element. That is the cost of recursion: order n extra memory, where the loop used order one.

Here is the call stack. The first call is at the bottom. Each new call is pushed on top. Seven calls, seven frames. When the top one returns, it is popped, and the one below continues.

9. Act Three — Searching recursively

Now searching, recursively. Linear search asks: is the key here? If not, search the rest. Twenty four is found after five comparisons, five calls deep. Binary search asks: is the key in the left half or the right half? Then it searches only that half. On the sorted week, three comparisons, three calls deep.

Binary search for twenty four. The first call looks at the middle, twenty three. Too small, so it calls itself on the right half. The second call looks at twenty five. Too big, so it calls itself on the left part. The third call finds twenty four. Three calls deep.

11. Act Four — Insertion, deletion and reversal, recursively

Insertion, deletion and reversal can also be recursive. To insert eighteen at index two, shift right calls itself from the last element down to index two. Five shifts, five calls deep. Deleting index zero shifts seven elements left, seven calls deep. And reverse swaps the two ends, then reverses what is between them. Three swaps, three calls deep.

Here is reverse. The first call swaps the two ends. The second call swaps the next pair in. The third call swaps the pair next to the middle. The middle element has nothing to swap with. That is the base case.

14. Act Five — The limit of recursion

And the limit of recursion. Binary search on a million elements goes only twenty calls deep, because each call halves the range. Linear search on the same million needs one frame per element. The call stack runs out, and Java throws a stack overflow error. The loop version finishes, with order one extra memory. So, recurse when the depth is small, and use a loop for long linear passes.

15. The limit of recursion

Here are the two depths side by side. Binary search, twenty frames. Linear search, a million frames, far more than the call stack can hold. The work is similar in style. The depth is what matters.

16. Time and Space Complexity

Here are the costs. Access and update are order one, and are not recursive. Traversal, linear search, maximum and sum take order n time, and order n stack space, one frame per element. Binary search takes order log n time, and order log n stack space. Insertion and deletion shift up to n elements, with up to n frames. The loop versions take the same time, with order one extra space.

17. Recursive or Iterative?

Recursive or iterative? Both give the same answers, with the same number of steps. But recursion keeps a frame for every waiting call, and a loop does not. Binary search on a million elements needs only twenty frames, which is safe. Linear recursion on a million elements needs a million frames, and overflows. So recurse when the depth is logarithmic, and use a loop for long linear passes.

18. Common Mistakes

Five mistakes to watch for. Forgetting the base case, so the recursion never stops. Calling again without making the problem smaller. A base case that an empty array never reaches. Shifting from the insertion position upwards, which overwrites the data. And linear recursion on large data, which overflows the stack.
